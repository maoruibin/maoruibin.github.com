DeepSeek Agent 火了。

这个项目 8 月 13 日才开源，到今天也就两天，GitHub 上已经超过 10 万 star。

![DeepSeek 公告](https://gudong.s3.bitiful.net/img/1786779164500-fmc4jy.png)

这个速度太夸张了，可以说彻底爆了。

我昨天就装上了，也点开玩了一会儿。

![DeepSeek Agent 主页面](https://gudong.s3.bitiful.net/img/1786779315389-3b3v9u.png)

但我得先说清楚，我没有深入用，也没资格替它写一篇正儿八经的评测。

我只是翻了翻它的代码，又把它跟最近这些 Agent 工具放在一起想了想。

今天想聊的不是它有多好用，而是它为什么这么火。

### 1. 以前的 DeepSeek，只是个很聪明的大脑

DeepSeek 之前一直做模型。

网页打开能聊天，能写诗，能讲道理。

![网页版](https://gudong.s3.bitiful.net/img/1786779759601-d22s65.png)

但它不能干活。

你想让它帮你改个文件、跑个程序，它只能给你建议，不会伸手。

不过把它塞进 Claude Code 或者 Codex 里，它又能干活了。

因为干活这件事，不是模型在干，是外面那层 Agent 在干。

官方一直没把这层能力补上。

但这一年，风向变了。

![图 4：AI Agent 的风向变化](https://gudong.s3.bitiful.net/img/1786779397943-3ymntl.png)

从去年 10 月的 Claude Code，到小龙虾，再到现在的 Codex，大家都在做同一件事：

光聪明不够，你得能干活。

OpenAI、Anthropic 已经把这件事证明得很清楚了。

写代码、做 PPT、做视频，AI 干起来一个比一个猛。

DeepSeek 在这条路上，其实起步是晚的。

大概两个月前，他们才开始认真做让 AI 干活这件事。

### 2. DeepSeek Agent 的答案：一切都是插件

![DeepSeek Agent 主页](https://gudong.s3.bitiful.net/img/1786779436428-fohh2n.png)

它官方名字叫 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)，简称 DSH。

跟 Claude Code、Codex 完全不是一个路线。

它从发布第一天就是完全开源的。

核心就一句话：

一切都是插件。

模型怎么接，是插件。

工具怎么调，是插件。

任务怎么循环，是插件。

定时、看板、界面，这些都可以是插件。

你可以把它理解成一套乐高。

官方先把底座和卡扣做好，剩下的零件，谁都可以来拼。

而 Claude Code、Codex 更像是精装房。

你可以写 Skills，也可以写插件，但墙怎么动、水电怎么走，你是碰不到的。

插件什么时候运行、放在哪一层、能不能改流程，开发者说了不算。

DSH 不一样。

你觉得哪一层不舒服，就可以自己写一个插件，插进去。

### 3. 它让我想起 Obsidian

我做 inBox 笔记，笔记圈里有个软件叫 Obsidian。

很多人喜欢它，不是因为它本身多强。

是因为它的插件机制。

目录不好用，有人写目录插件。

展示不好看，有人写主题和渲染插件。

想把别的笔记软件里的东西同步过来，也有人写。

什么功能都能长出来。

前段时间我还开发了一个 Obsidian 插件，核心功能就一件事：用云账号把 inBox 笔记的内容同步到 Obsidian。

![我开发的 inBox 笔记同步插件，跑在 Obsidian 里](https://gudong.s3.bitiful.net/img/1786779983576-4eynbq.png)

DSH 现在做的，就是把 Obsidian 这套打法，搬到了 Agent 上。

而且比 Obsidian 还要彻底。

Obsidian 能换的是功能，DSH 连模型、存储、任务循环、界面壳都能换。

### 4. 社区这两天已经炸了

这才是 10 万 star 背后真正的原因。

Codex 功能再多，背后也就是 OpenAI 一个团队，最多几百个人。

DSH 这么一开放，全世界的 AI 开发者都可以往里塞东西。

这两天已经有人写出浏览器插件。

让 DSH 可以打开网页，逐秒截屏，再做 OCR。

这样它就能“看视频”了。

还有人做了桌面版、CLI 版。

定时任务、任务看板，也在往外冒。

这不再是几百个人做一个工具。

这是把全球开发者，都变成了它的外挂团队。

### 5. 我暂时还是 Codex + Z-Code

说了这么多，但说实话，我暂时不会换。

现在主力还是 Codex，再加上 Z-Code。

原因很具体。

我本来买了智谱的年度套餐，GLM-5.3 昨天发布，我用下来感觉非常好。

DeepSeek 我昨天简单试了一下，速度还是不够快，而且还得单独花钱买它的模型。

Codex 和 Z-Code 现在也已经很强了。

任务执行、手机端、自动化这些，功能都比较全，我的很多习惯也都已经长在那边。

还有一个很现实的原因：

我更喜欢桌面端。

DSH 现在还只是 Web 端，这对我来说还不够顺手。

不过我觉得后面它一定会出桌面版。

就算官方不出，社区也会很快有人去做。

![社区的开源桌面版](https://gudong.s3.bitiful.net/img/1786779686337-tyqr2j.png)

### 6. 但我不会只当观众

DeepSeek Agent 的负责人也说了，现在还是很早期的阶段。

所以我会先关注，先观望，慢慢再加入。

我估计像我这样的人很多。

大家不是不感兴趣，只是更理性，不想在新东西还不稳的时候直接搬家。

但我后面大概率会去研究它的插件。

尤其是我最近一直想做一件事：

任务看板。

我一直希望 Codex 和 Z-Code 能加一个看板，让我更直观地管理任务。

这个需求，在 DSH 的插件机制下，可能自己就能写出来。

这也是我对它最感兴趣的地方。

这段时间 DeepSeek 连着发 V4、Flash，已经很热闹了。

但真正让我觉得提气的，还是这次 Agent。

一个中国的开源项目，敢把 Agent 的底层全拆开给大家玩。

**这件事比单个模型跑分更有想象力。**

我现在不下“它会干掉谁”的判断。

我只说我会做的：

**先继续用 Codex 和 Z-Code，同时盯着 DSH，等它再长一长。**
